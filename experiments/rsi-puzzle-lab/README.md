# RSI Puzzle Lab — 受限自改进实验

本次正式实验已结束。程序实际持续运行 **1860.996 秒（31 分钟）**，不是计划时长，也不包含此前两次失败控制器运行。独立目录、独立分支，不改原 Cocos 插件，不合并 main。

## 先看结果

| 指标 | 初始 G0 | 最终 G10 |
|---|---:|---:|
| 固定验证集最优通关 | 58 / 256 | 256 / 256 |
| 验证集平均计费扩展 | 768.3828125 | 35.75390625 |
| 最终保留集最优通关 | 112 / 512 | 512 / 512 |
| 保留集平均计费扩展 | 773.2578125 | 38.3359375 |

正式循环完成 **2,915 个不同候选**的实测，接受 **10** 次改进，拒绝 **2,905** 个候选。另有 **9,028** 次重复或语法守卫跳过，不计入不同候选实测数。CPU 时间为 **1860.315 秒**。

**最后一次提升发生于第 24.996 秒。** 此后的约 30 分 36 秒持续搜索，没有发现更强候选。图表按真实分钟显示活动量，不把平台期包装成持续变强。平均计费扩展的下降也不等于同比例的运行提速。

`results/final-history.csv` 保存每代实测值；`results/champions/` 保存 G0–G10 可编译源码；`results/final-summary.json` 保存最终摘要。完整 JSONL、逐关细节、HTML 面板、失败运行、截图和校验清单位于本次会话交付的 ZIP。GitHub 保存源码和精简证据，并未保存整份原始 JSONL。

## 这次的“自改进”是什么

当前策略 → 受限变异 / 历史候选探索 → 编译与下界证书检查 → 固定训练集评估 → 固定验证集验收 → 胜者接管并保存源码 → 下一轮继承。

候选可组合已有启发式、改变同分搜索顺序，并从已测的有效历史候选继续探索。变异调度使用尝试次数、收益、重复惩罚和探索归档。候选不能在表达式中读文件、导入模块或访问完整棋盘答案。

**这不是开放式 RSI，也没有训练基础模型权重。** A*、曼哈顿距离、线性冲突与模式数据库工具由工程预先提供。正式循环为本地程序合成，外部大模型调用为 **0 次**。本次对话模型负责搭建工程，并根据真实故障日志修复控制器；不得把这两次源码修复说成本地变异器自主发明。

## 固定验收与边界

每关最多 900 个有效节点扩展。每条通关路径由独立验证器逐步重放，长度须等于反向 BFS 给出的最优距离。失败关在聚合成本中按 900 计费。训练 / 验证 / 保留集为 128 / 256 / 512，棋盘互不重叠。

数据按最优距离分层抽样，固定种子 20260924；31 步状态非常稀少，不保证每个 split 都包含 31 步关卡。完整 oracle 共 181,440 个可达状态。正式保留集只在搜索结束、冠军冻结后审计一次，同时报告历史冠军，但不据此再选冠军。

协议由预注册 Git 提交 `57540f1aed2e607070417f47b070c99df0a7f19a` 固定。运行时逐轮检查 `domain.py`、`strategy.py`、`evaluator.py` 和四份数据文件的 SHA-256。控制器 v3 的启动与结束源码指纹一致。哈希检查是防意外篡改措施，不是对恶意宿主或任意代码的操作系统级隔离。

## 真实故障与修复

控制器 v1 把“没有形成新候选”当作“尚未尝试”，导致同一操作饥饿式占用调度。它运行 101.603 秒，只完成 6 个不同候选。改为按尝试计数，并增加回归测试。

控制器 v2 只保留冠军，有限的一跳邻域被耗尽。它运行 408.265 秒，完成 571 个候选，随后空转。正式 v3 增加有效非冠军归档、分支探索和防空转检查，重新启动独立 31 分钟实验。

同一个调度回归案例在旧 v1 中 30/30 次只选到耗尽操作；修复后为 1/30 次，其余六类操作均能被访问。v1 没有在启动日志记录自身源码哈希，其备份仅作为故障源码快照；v2、v3 的源码与启动指纹已核对。

## 强对照与复现

人工组合全部已有工具，在验证集上同样达到 256/256、平均计费扩展 35.75390625；自动所得策略**持平而非超越**这个强对照。单组模式数据库的扩展量更高，但实测耗时反而更低，说明本实验目标不是最短运行时间。详见 `results/strong-controls.json`。

额外预选三个种子 7、42、20260924，各运行 90 秒，均达到同一验证集 256/256；这不是跨领域泛化证明，也未用于改选正式冠军。详见 `results/repeated-seeds.json`。

## 运行

核心仅用 Python 标准库；本次实测环境为 Linux / Python 3.13.5。建议 Python 3.10 或以上，Windows 下启用 UTF-8 模式。Windows 和 macOS 未做真机验收。

```bash
cd experiments/rsi-puzzle-lab
python run.py --seconds 1860 --name replay-01
```

在交付 ZIP 内，则进入 `rsi-puzzle-lab` 目录后执行相同命令。Windows PowerShell 可先执行 `$env:PYTHONUTF8="1"`。程序拒绝覆盖同名运行；换名称即可再次复现。输出 `runs/replay-01/` 和 `report-replay-01.html`。

固定策略在固定关卡上的路径和计费节点可复现；按真实时间截止的候选数量、完整轨迹可能因机器速度与调度而不同，不保证整份日志逐字节相同。干净目录重建已验证三份关卡数据字节指纹一致；`python run.py --seconds 3 --name wrapper-smoke` 的完整流水线也已实测通过，未计入正式 31 分钟。

```bash
python -m unittest tests -v
python audit_run.py --run runs/replay-01 --recheck 24
python build_report.py --run runs/replay-01 --out replay.html
```

可选浏览器验收需要 Playwright 与 Chromium；实验本体及离线面板不依赖它们。`ci.example.yml` 只是手动工作流示例，未启用，本次没有声称运行过 GitHub Actions。

## 本次验收

53 项单元测试全通过；干净目录缺少历史 smoke 文件时，有 1 项历史核对会跳过。14 个主要 Python 模块通过字节码编译。最终面板通过 16 项浏览器交互检查，并覆盖 55 个版本/关卡组合、970 个实际路径状态。

最终独立审计检查全部 2,915 个候选的唯一 ID、父代、源码指纹和接管条件，并重执行 34 个候选（包含全部 10 个获准接管版本），结果指纹一致。正式循环中相邻新候选完成记录的最大间隔约 5.881 秒。

实验已停止。HTML 只重放已保存的路径，不会在后台继续训练，也不会伪造自动增加的运行时间。
